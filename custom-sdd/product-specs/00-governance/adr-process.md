# ADR Process

Create an ADR for a significant architecture, communication, security, data, or migration decision.

1. Draft the context and alternatives.
2. Record the decision and consequences.
3. Obtain architecture and specialist review.
4. Mark the ADR `ACCEPTED`, `REJECTED`, or `SUPERSEDED`.
5. Link the ADR from affected specifications and JIRA tickets.

Dummy example: `ADR-001` defines event-driven customer notifications.
